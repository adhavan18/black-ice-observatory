# historical simulation

this document is a research scenario, not a real record of past development.

the git history, github pull requests, commit dates, and review comments remain the source of truth for what actually happened. the timeline below shows how the project could have developed over a year if it had started twelve months earlier.

## simulated twelve-month plan

| simulated month | milestone | research focus |
|---|---|---|
| month 1 | define the safety boundary | non-executing analysis and sample handling |
| month 2 | build indicator extraction | hashes, urls, domains, and source confidence |
| month 3 | add signature detection | explainable rules and false-positive review |
| month 4 | add behavior profiling | named features, weights, and analyst feedback |
| month 5 | normalize intelligence reports | internal and external source processing |
| month 6 | add adversary tracking | aliases, campaigns, techniques, and confidence |
| month 7 | add intelligence requirements | turn unknowns into collection tasks |
| month 8 | add response planning | evidence, containment, recovery, and approvals |
| month 9 | add security reviews | defects, guidance gaps, and ownership |
| month 10 | design high-scale ingestion | queues, partitions, retries, and backpressure |
| month 11 | add ci and security checks | tests, secret scanning, and safe sample policy |
| month 12 | prepare integrations | siem, edr, case management, and approved sandbox boundary |

## how to use this for research

use this timeline to compare planned maturity against the real implementation. do not present the simulated months as historical github activity, employment history, or evidence that the system was deployed during that period.

## real project status

the current repository contains a safe static-analysis prototype with synthetic input, unit tests, ci workflows, and documentation. it does not execute malware and it has not been connected to a live production sandbox, siem, edr, or cloud account.
